# ログイン機能 改修 変更箇所一覧（ver 3.1）

対象: `agri-erp-supabase`（Supabase版 / 単一HTML配布）
改修内容: ①`Cannot read properties of null (reading 'loginSecurity')` の不具合修正 ②緊急管理者ログインの追加 ③設定画面のオン／オフ

---

## 1. 不具合の原因

`src/06-app.js` の `boot()` は Supabase 接続に失敗すると **`return` で処理を中断** し、
`Store.load()`（＝`Store.db` の初期化）を実行しませんでした。
一方ログイン画面のボタンは有効なままなので、押下すると `Auth.doLogin()` が
`Store.db.loginSecurity` を参照して **`Store.db === null` により例外**となっていました。

```
boot() → SB.init() 失敗 → return（Store.db は null のまま）
       → ログインボタン押下 → doLogin() → Store.db.loginSecurity → TypeError
```

## 3. 緊急管理者ログインの仕様

| 項目 | 値 |
|---|---|
| ユーザーID | `tom` |
| パスワード | `zep` |
| 権限 | `admin`（管理者） |
| 表示名 | 緊急管理者 |
| 判定順序 | **通常ユーザー認証より先**（Supabase RPC・ローカル照合より前） |
| 依存 | Supabase 接続状態・`Store.db` 初期化状態に依存しない |
| 遷移先 | 常にダッシュボード |
| 有効条件 | 設定画面「緊急管理者ログインを有効化」が ON（**既定 ON**） |
| データへの影響 | `users` テーブル／Supabase のユーザー行には**追加しない**（既存データを汚さない） |
| 記録 | 監査ログに `emergency_login`（実行者・日時）を記録。パスワードは記録しない |
| ログアウト | 通常ユーザーと同じ（`Auth.logout()`）。セッション復元も設定 ON の間のみ有効 |

### 入力の正規化
ユーザーIDは前後空白の除去と小文字化を行ってから判定します（`  TOM ` でも一致）。
パスワードは大文字小文字を区別します（完全一致）。

## 4. 運用上の注意（重要）

- 本アプリは **静的配布物（単一HTML）** のため、認証情報はソースに含まれます。配布先の端末・共有フォルダを限定してください。
- 配布範囲を限定できない場合は、次のいずれかを併用してください。
  1. 構築時に `EMERGENCY.LOGIN_ID` / `EMERGENCY.PASSWORD` を貴社固有の値へ変更（`src/02-core.js`）
  2. 運用が安定したら設定画面で **緊急管理者ログインを無効化**
  3. リバースプロキシ等で `/emergency-login` 相当の経路を IP 制限
- 緊急ログインの利用状況は監査ログ（ユーザー管理画面の「操作ログ」）で確認できます。
- Supabase に接続できない場合、アプリは **オフラインモード**（このセッション内のみ）で起動します。本番データは変更されません。

## 5. 検証結果

| 検証 | 結果 |
|---|---|
| `node --check src/*.js` / `build/bundle.check.js` | OK |
| `npx eslint build/bundle.check.js` | エラー 0 |
| `node scripts/smoke_supabase.js` | 27 項目 ALL PASS（同期・認証・削除順序・競合保護） |
| `node scripts/ui_smoke_issuer.js` | 45 項目 ALL PASS（会社・拠点・帳票） |
| `node scripts/login_smoke.js` | **33 項目 ALL PASS**（下記） |

`login_smoke.js` の主な検証項目:
- `Store.db === null` の状態でも `doLogin` が例外を投げず `not_ready` を返す（**報告された不具合の再現テスト**）
- 同状態でログイン画面の送信がクラッシュせず、エラーメッセージを表示する
- 同状態で `tom` / `zep` によりログインでき、`role='admin'`・ダッシュボード遷移・緊急バナー表示
- 緊急ユーザーが `users` に追加されないこと／監査ログに記録されること
- 設定 OFF で緊急ログインが拒否され、**既存ユーザー認証は維持**されること
- `admin` / `office` / `shipping` が従来どおりログインできること（誤パスワード・不存在ユーザー・空入力の拒否）
- Supabase 接続失敗時にオフラインで起動し、警告とバナーが出て、緊急ログインが可能なこと
