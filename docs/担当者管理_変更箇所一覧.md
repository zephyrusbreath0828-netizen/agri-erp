## 2. データベース改修（`sql/10_add_owner_fields.sql`）

新規SQL 1本のみ。冪等（`add column if not exists`）。既存行の削除・更新は行いません。

| テーブル | 追加列 | 型・制約 | 用途 |
|---|---|---|---|
| orders | `sales_user_id` | text → users(id) ON DELETE SET NULL | 担当営業 |
| purchase_orders | `purchase_user_id` | 同上 | 発注担当 |
| receipts | `receipt_user_id` | 同上 | 受入担当 |
| shipments | `shipment_user_id` | 同上 | 出荷担当 |
| stock_movements | `owner_id` | 同上 | 入出庫履歴の担当者 |
| users | `owner_code` / `department` / `extension` | text | 担当者コード・担当部署・内線番号 |
| users | `company_id` / `branch_id` | text → companies(id) / branches(id) | 所属会社・所属拠点 |
| doc_templates | `owner` | boolean not null default true | 帳票の担当者表示 |
| audit_logs | `detail` / `doc_kind` / `doc_no` / `organization_id` | text / bigint | 担当者変更の内容 |

インデックス：`(organization_id, sales_user_id, order_date)` ほか4本、`users(organization_id, owner_code)`、`audit_logs(doc_kind, doc_no)`。

> 旧 `sales_rep_id`（ver 3.2）と `received_by` は削除せず残しています。アプリは
> 「新列 → 旧列」の順で読み替えるため、旧データの担当者はそのまま表示されます。
> 一括で新列へ移す場合のみ、SQL 末尾のコメントアウトした `update` を実行してください。

## 5. 権限制御

| ロール | 閲覧範囲 | 担当者の変更 |
|---|---|---|
| system_admin | 全組織（画面はログイン組織のデータ、組織マスタで全組織の件数を参照） | 可 |
| org_admin | 自組織のみ | 可 |
| manager | 自組織のみ | 可 |
| user | 自組織。既定は**自分の担当案件のみ**（未設定の旧データは表示）。システム設定で「自組織すべて」に変更可 | 可 |

- 担当者候補は**常にログイン組織のユーザーのみ**（他組織のユーザーは一覧・プルダウン・CSVに出ません）。
- 設定は `settings.owner_scope`（アプリ内 `settings.ownerScope`）＝ `mine` / `org`。
  「担当者別実績」画面のチップ、またはシステム設定から切替できます。

## 6. 既存データの扱い

- 追加列は NULL 許可。**既存レコードは削除・更新していません**。
- 旧データは担当者「未設定」として表示（一覧は「未設定」、集計は「（未設定）」行にまとまる）。
- 旧 `orders.sales_rep_id` / `receipts.received_by` は同等の意味のため**読み替え表示**（データ移行なし）。
- 新規作成時のみ担当者を保存します。

## 7. 適用手順

1. `sql/10_add_owner_fields.sql` を Supabase SQL Editor で実行（既存DBに追加列を作成）。
2. アプリを再ビルドして配信：
   ```
   python3 build/assemble.py --dist     # または node build/assemble.js --dist
   ```
3. ブラウザを再読み込み（Service Worker 等は未使用のためキャッシュクリアは不要）。
4. ユーザー管理で各ユーザーの「担当者コード・部署・内線・所属会社/拠点」を設定。
5. 必要に応じて「担当者別実績」で表示範囲（自分の担当のみ／自組織すべて）を決定。

> SQL未実行でもアプリは起動しますが、担当者列の同期は行われません（画面上は選択・保存が可能で、リロード後に消える可能性があります）。必ず先にSQLを適用してください。

## 9. 補足・注意

- 「受注書」は本システムに独立した帳票がないため、受注ベースの**見積書**に担当者を印字しています（請求書・納品書も同様）。
- 担当者を変更しても、過去に発行済みの帳票（`documents` のスナップショット）は変更されません。再発行時に最新の担当者が印字されます。
- 監査ログはユーザー管理画面の「操作ログ」に表示されます（`audit_logs` テーブルにも保存）。
- 担当者コードは任意項目です。未設定の場合は氏名順で並びます。
