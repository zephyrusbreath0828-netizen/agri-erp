# 権限管理（ロール）改修 — 変更箇所一覧（ver 3.5）

## 目的
Agri-ERP の権限を **system_admin / org_admin / manager / user** の4ロールへ再編し、
画面のアクセス制御と Supabase RLS（`organization_id`）を同じ規則で整合させる。

## ロールと権限

| ロール | 組織マスタ | 全組織閲覧 | 全ユーザー閲覧 | システム設定 | 自組織の会社・拠点・テンプレート | 自組織のユーザー管理 | 業務画面 |
|---|---|---|---|---|---|---|---|
| system_admin | ○ | ○ | ○ | ○ | ○ | ○（全組織） | ○ |
| org_admin | × | × | × | × | ○ | ○ | ○ |
| manager | × | × | × | × | 参照のみ | × | ○ |
| user | × | × | × | × | × | × | ○ |

- **組織マスタ画面（`organizations`）は system_admin 以外にはメニュー自体を出さない**（`sysOnly` + 画面内ガードの二重）。
- org_admin が付与できるロールは **manager / user のみ**（system_admin / org_admin は付与不可）。
- システム管理者が不在にならないよう、降格・無効化・削除は「同一組織に有効な管理者が残る場合」のみ許可。

## アクセス制御の実装ポイント

1. **メニュー**: `MENU[].roles` に4ロールを明示。`organizations` / `settings` は `sysOnly: true`。
2. **画面**: `Auth.can(page)` が `Role.of(user)` で判定（`sysOnly` は system_admin のみ）。
3. **操作**: `Actions.userForm/saveUser/toggleUserEnabled/deleteUser`、`IssuerAdmin.companyForm/branchForm/templateForm` でガード。
4. **データ**: 非 system_admin は `Store.db` が自組織のみにスコープ（ver 3.4 の仕組みを継承）。system_admin は「全ユーザー閲覧」のため `users` のみ全組織を保持し、全組織の集計は `Tenant.raw()` で参照（業務画面・帳票は自組織に固定して混線を防止）。
5. **DB(RLS)**: `using (public.is_system_admin() or organization_id = public.current_org_id())` と同条件の `with check`。組織マスタの変更は `is_system_admin()` のみ。

## 適用順序
1. `sql/09_roles_permissions.sql` を Supabase SQL Editor で実行（`08_multi_tenant.sql` の後・冪等）
2. `build/agri-erp-supabase.html`（または `.aspx`）を差し替え
3. 既存ユーザーは自動で読み替え：`admin`（フラグ有/`admin` ID）→ system_admin、その他の `admin` → org_admin、`office`/`shipping` → user
