# 会社・拠点マスタ／伝票発行元 改修ガイド（ver 3.0）

## 1. 概要
単一の「自社情報」設定を廃止し、**会社マスタ（複数登録）**と**拠点マスタ（会社 1:N）**を新設しました。
伝票（見積書・発注書・納品書・請求書・入庫伝票・出庫伝票・ピッキングリスト）には、
伝票ごとに選択した **発行会社＋発行拠点①②** が印字されます。

| 項目 | 改修前 | 改修後（ver 3.0） |
|---|---|---|
| 発行元 | `app_settings.company`（単一会社・1件） | `companies`（複数）＋ `branches`（会社ごとに複数） |
| 伝票の発行元 | 全伝票で同一 | 伝票ごとに 会社1件＋拠点最大2件を選択 |
| 表示項目 | 固定 | マスタの表示可否 × 帳票テンプレートで制御 |
| 帳票種別 | 納品書・出荷伝票・ピッキング | ＋見積書・請求書・発注書・入庫伝票 |
| 帳票レイアウト | 固定 | 帳票テンプレート（9種類を初期投入） |

## 2. 追加テーブル
- `companies` … 会社コード / 会社名 / 郵便番号 / 住所 / TEL / FAX / メール / 適格請求書登録番号 / ロゴURL / 備考 / 有効無効 / 表示可否(`visible_fields` JSONB)
- `branches` … 会社ID（FK）/ 拠点コード / 拠点名 / 郵便番号 / 住所 / TEL / FAX / メール / 担当者名 / 備考 / 有効無効 / 表示可否
- `doc_templates` … テンプレートコード / 名称 / 帳票種別 / 対象会社 / 表示項目9種 / 標準フラグ / 有効無効

## 3. 追加カラム（外部キー）
`orders` / `purchase_orders` / `receipts` / `shipments` / `documents` に
`company_id` → `companies(id)`、`branch1_id` / `branch2_id` → `branches(id)` を追加。
`documents` には `template_id`（→ `doc_templates`）、`po_id`、`receipt_id` も追加。

## 4. 既存DBへの適用手順
1. Supabase SQL Editor で **`sql/05_add_companies_branches.sql`** を実行（冪等・何度実行しても安全）
2. **`build/agri-erp-supabase.html`（または .aspx）** を再配置（接続設定は変更不要）
3. 画面「システム → 会社・拠点マスタ」で会社・拠点を確認／追加
4. 画面「システム → 帳票テンプレート」でテンプレートを確認／調整

新規構築の場合は従来どおり `sql/01_create_tables.sql` → `sql/02_seed.sql`（ver 3.0 対応済み）。

## 5. 画面操作（伝票作成時）
```
発行会社（必須）
  ↓ 選択すると配下の拠点だけに絞り込み
発行拠点①（任意）
  ↓
発行拠点②（任意・①と重複不可）
```
受注登録・発注登録・入荷処理・出荷指示の各フォームに「発行元情報」欄があり、
選択内容はフォーム下部のプレビューに即時反映されます。登録した発行元は伝票ヘッダーに保存され、
帳票発行時にそのまま印字されます。

## 6. 表示制御の優先順位
帳票へ出力するかは **「帳票テンプレートのチェック」 AND 「会社／拠点マスタの表示可否」** で決まります。
- 非表示にした項目、値が空の項目は **HTML自体を出力しない**（空行・空白領域を作らない）
- 住所を非表示にすると郵便番号も出力しない
- ロゴはURLが登録されている場合のみ印字
- 拠点②未選択時は【拠点②】ブロックを出力しない

## 7. 帳票テンプレート（初期投入）
標準見積書 / 簡易見積書 / 標準発注書 / 簡易発注書 / 標準納品書 / 標準請求書 / 標準入庫伝票 / 標準出庫伝票 / 標準ピッキングリスト。
帳票種別ごとに「標準」テンプレートが自動適用されます（会社専用テンプレートがある場合はそちらが優先）。

## 8. 既存データの移行
- `app_settings.company`（旧・自社情報）は、会社マスタが空のとき **自動で `companies` へ移行**（アプリ起動時／SQL実行時）
- 既存伝票の `company_id` は NULL のまま保持し、**帳票出力時は既定会社（先頭の有効会社）で印字**（従来の見た目を維持）
- 既存の受注・発注・在庫・帳票番号などのデータは一切変更しません

## 9. 動作確認
```
node --check build/bundle.check.js     # 構文チェック
node scripts/smoke_supabase.js         # Supabase同期・認証のスモークテスト
node scripts/ui_smoke_issuer.js        # 会社・拠点・テンプレート・帳票のUIテスト（要 jsdom）
```

## 10. 既知の制約
- 伝票の宛先（得意先／仕入先）マスタには会社・拠点の紐付けはありません（発行元のみの対応）
- ロゴは画像URLのみ対応（Supabase Storage へアップロードした公開URLを登録してください）
- 発行元の変更は既存伝票には影響しません（発行時点のスナップショットを保持）
